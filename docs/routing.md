# 경로 계산 설계

## 전체 흐름

`services/routePlanner.ts` → `planRoute()`

1. **노드 목록**: 출발지(0번) + 방문 장소 + 도착·복귀 거점 후보 (id 기준 중복 제거)
2. **구간 행렬**: 노드 쌍마다 선호 수단별 이동 정보 (거리·시간·요금·경로 좌표)
3. **구간 비용**: 선호 수단 중 기준(거리/시간/비용)에 가장 유리한 수단의 값
4. **순서 최적화**: 거점 후보 조합마다 방문 순서를 최적화하고 가장 좋은 조합을 선택
5. **확정**: ("추정 후 확정" 방식이면) 최종 경로의 구간만 API로 다시 조회해 실제 값으로 교체

## 순서 최적화 (`lib/tsp.ts`)

출발점이 정해진 TSP의 변형이다. 끝점은 경우에 따라 다르다.

| 상황 | start | end |
| --- | --- | --- |
| 복귀 안 함 | 출발지 | 없음 (마지막 장소에서 끝) |
| 복귀 (기본값) | 출발지 | 출발지 |
| 거점 사용 | 도착 거점 | 복귀 거점 → (그 뒤 출발지) |

- 방문지 **10곳 이하**: Held-Karp 동적계획법으로 정확한 최적해를 구한다. O(2ⁿ·n²)
- **10곳 초과**: Nearest Neighbor로 초기해를 만들고 2-opt로 개선한다 (근사해). 행렬이 비대칭(대중교통)일 수 있어서, 구간을 뒤집을 때마다 전체 비용을 다시 계산한다.
- 기준을 바꿔도 알고리즘은 같다. 비용 행렬만 바뀐다.

## 경유 거점

다른 도시로 가는 여행에서, 여행지에 들어가고 나오는 기차역·터미널이 서로 다를 수 있다.

```
대전 집 ─(대중교통: 대전역→KTX)→ 서울역 → 장소들 … → 영등포역 ─(대중교통: 무궁화→서대전역)→ 집
         ^ 도착 거점 후보: 서울역, 용산역      ^ 복귀 거점 후보: 서울역, 영등포역
```

- 사용자는 **여행지 쪽 거점만** 후보로 넣는다. 집 ↔ 거점 사이의 기차·버스·도보 환승은 대중교통 API가 한 구간으로 찾아준다.
- 도착 후보 × 복귀 후보의 모든 조합에 대해 `출발지→도착거점` + `최적 순서` + `복귀거점→출발지` 총비용을 비교한다. 후보는 보통 2~3개라 전수 비교로 충분하다.
- 마지막 방문지에 따라 복귀 거점이 달라진다. 예를 들어 홍대·여의도에서 끝나면 서울역보다 영등포역이 유리하다 (테스트: `optimizer.test.ts`).

## 이동 수단

### 선호 수단 (1~3개)

- 1개만 고르면 모든 구간을 그 수단으로 계산한다.
- 여러 개를 고르면 구간마다 그중 기준에 가장 유리한 수단을 쓴다. 단 도보는 `WALK_MAX_KM`(2km) 이내 구간만 쓴다. 이 제한이 없으면 "최소 비용"에서 항상 도보가 뽑힌다.
- 수단을 셋 다 켜면 수단별 속도 차이 때문에 한 수단이 대부분 뽑힌다 (예: 최단 시간 → 택시). 그래서 사용자가 원하는 수단만 고르게 했다.

### 구간 재검색

결과 화면에서 지점 두 곳(시작 → 끝)을 누르면 그 사이 구간들이 선택된다. 다른 수단을 골라 재검색하면 **해당 구간만** API로 다시 조회한다. 방문 순서는 유지되고, 합계는 다시 계산된다. 재검색한 구간에는 "재검색됨" 표시가 붙는다. "다시 계산"을 누르면 초기화된다.

## 요금 계산

`lib/fare.ts` → `groupFareKrw(leg, passengers)`

| 수단 | API가 주는 값 | 일행 비용 |
| --- | --- | --- |
| 도보 | — | 0 |
| 대중교통 | 성인 1인 요금 (`fare.regular.totalFare`) | 분류별 할인 규칙 × 인원 |
| 택시·자동차 | 차량 1대 택시 요금 (`taxiFare`) | 요금 × ⌈총인원 / 4⌉대 |

### 대중교통 할인 규칙 (성인 요금 대비)

| 분류 | 시내 (버스·지하철) | 기차·고속/시외버스·항공 포함 구간 |
| --- | --- | --- |
| 성인 | 100% | 100% |
| 청소년 (13~18세) | 900/1550 ≈ 58% | 100% |
| 어린이 (6~12세) | 550/1550 ≈ 35% | 50% |
| 영유아 (6세 미만) | 무료 | 무료 (좌석 미점유 기준) |
| 경로 (65세 이상) | 지하철만 이용 시 무료, 버스 포함 시 성인 요금 | 70% |
| 장애인 | 지하철만 이용 시 무료, 버스 포함 시 성인 요금 | 50% |

- 시내 요금 비율은 수도권 교통카드 요금(2025.6 인상 후 성인 1,550 / 청소년 900 / 어린이 550원)에서 가져왔다.
- 경로·장애인은 한 구간 안에서 지하철과 버스 요금을 나눌 수 없어서, 버스가 섞이면 성인 요금으로 보수적으로 계산한다.
- 광역 수단 할인율은 대표값 근사다. 노선·열차 종류·시기에 따라 다르다.

## API 호출 전략

설정 탭에서 선택한다 (`MatrixStrategy`).

| 방식 | 순서 결정 | API 호출 수 (장소 N곳, 수단 M개) |
| --- | --- | --- |
| **추정 후 확정** (기본) | 직선거리 추정 행렬 | ≈ 경로 구간 수 × M |
| 전체 조회 | 모든 쌍을 API로 | ≈ N² × M |

- 같은 구간·수단·출발시각 조회는 앱 실행 동안 캐싱한다 (`cachedLeg`).
- 추정 방식은 순서가 실제 최적과 조금 다를 수 있다. 대신 장소가 10곳이면 호출 수가 수백 건에서 수십 건으로 줄어든다.

### 동시 호출 제한

TMAP 같은 API는 무료/평가판 등급에서 **초당 호출 수(burst rate)** 제한이 낮은 경우가 많다. 확정된 구간들을
`Promise.all`로 한꺼번에 다 쏘면 총 호출 수는 적어도 순간적으로 요청이 몰려 `429 QUOTA_EXCEEDED`를 만날 수 있다.
그래서 구간 API 호출은 `mapWithConcurrency`(`lib/concurrency.ts`)로 동시 요청 수를 제한한다:
방문 순서 확정(`planRoute`)과 구간 재검색은 한 번에 최대 2개, "전체 조회" 행렬은 최대 3개까지만 동시에 실행한다.
그래도 429가 반복되면 콘솔에서 해당 상품의 초당/일일 호출 한도를 확인하고, 등급을 올리거나 값을 낮춰야 한다.
